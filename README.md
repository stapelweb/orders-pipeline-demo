# Конвейер данных: источник → приведение → хранилище → экран

Небольшой рабочий пример: забрать заявки из внешнего источника, привести к
одному виду, схлопнуть дубли, положить в базу и собрать по ним экран —
один HTML-файл, который открывается с телефона.

Запускается на вложенных данных, без ключей и без сети:

```
python -m pipeline all
python tests/test_pipeline.py
```

На выходе `data/dashboard.html`.

## Что здесь показано нарочно

Не «ещё один ETL», а четыре места, на которых интеграции ломаются молча.
Каждое закрыто тестом.

**Источник отвечает не только двумястами.** Есть 429, 403, 5xx и обрыв.
Поэтому запрос с повторами и нарастающей паузой, и разделение: 429 и 5xx
повторяем, остальные 4xx — нет, там повтор бессмыслен.

**HTML-сущности.** Сумма приходит как `12&nbsp;000&#8381;`. Без `unescape`
разбор даёт ноль — и это не падает, а тихо занижает итоги. Такую ошибку
находят по расхождению в отчёте через неделю.

**Телефон — ключ, а не украшение.** Пока он не приведён к одному виду,
`8 (912) 345-67-89` и `+7 912 345 67 89` остаются разными людьми. При этом
догадок не делаем: семёрка дописывается только десятизначному номеру с
девятки, где результат однозначен; всё прочее честно отбрасывается.

**Дубли схлопываются с правилом, а не «последняя побеждает».** Повторная
заявка часто приходит укороченной, без суммы. Правило «последняя побеждает»
обнулило бы то, что мы уже знали, поэтому выигрывает запись с большей суммой,
а при равенстве — поздняя. Порядок на выходе зафиксирован: ответ не должен
плавать между прогонами.

**Идемпотентность проверяется, а не обещается.** Тест прогоняет сбор дважды
и требует, чтобы второй раз не создал ни одной новой записи и ничего не
переписал без причины.

## Структура

```
pipeline/collect.py   забрать, привести, схлопнуть, сохранить
pipeline/report.py    экран по базе: один самодостаточный HTML
fixtures/orders.json  девять заявок: дубли, сущности, запись без телефона
tests/                проверки — по одной на каждую ошибку выше
```

## Чего здесь нет

Docker, CI и миграций — намеренно: пример должен запускаться одной командой
на чистой машине с одним Python и без зависимостей. В рабочих проектах
расписание держу в планировщике, а не в оркестраторе.
